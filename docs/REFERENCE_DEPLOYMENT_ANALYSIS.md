## BoundaryOS path and diagnosed causes

BoundaryOS pins `genlayer-py==0.16.3` and `genlayer-test==0.29.2`. `create_client(chain=studionet, endpoint=...)` configures the official SDK client and `write_contract` submits `eth_sendRawTransaction`, waits for an EVM receipt, and extracts the GenLayer ID from `NewTransaction`. The resumable harness instruments that supported SDK path to preserve transaction identity across interrupted polling. It uses a separate raw JSON-RPC client for bounded status and finalized-state reads. This is the documented compatible path for non-payable contract writes; AuditLot's CLI payable-call issue is not a reason to replace it.

The failed probes are separable:

1. **RPC egress:** the current process sets `CODEX_SANDBOX_NETWORK_DISABLED=1`. A direct, read-only `eth_chainId` request to `https://studio.genlayer.com/api` failed with Windows `WinError 10013` before an HTTP response. An earlier harness attempt had the same connection failure after five retries. This is an execution-sandbox network restriction, not evidence of Cloudflare 502, an RPC JSON-RPC error, or a BoundaryOS execution defect. The historical Cloudflare 502 after the disposable proposal broadcast is a distinct server/proxy response.
2. **CLI profile access:** the regular Codex process still gets `EPERM` on `chmod C:\Users\USERpc\.genlayer`; an approved elevated invocation of the official CLI 0.40.0-rc.3 successfully listed the existing profile. The active network is Studionet, the selected named wallet is `my-studionet-wallet`, and a separate unlocked, funded account is available. Neither account keys nor wallet files were read, exported, copied, or changed. The network and profile are therefore reachable through the supported elevated command route even though ordinary sandboxed commands remain restricted.
3. **Signing configuration for the Python live suite (historical blocker, resolved):** checked-in `gltest.config.yaml` has `studionet: {}` and there is no project `.env`; `gltest` generates ephemeral default accounts when none are configured. This harness originally had no bridge from named CLI accounts to the SDK signer. The installed official CLI's deploy-script SDK has since been verified with both named accounts, allowing signing without reading or exporting key material. See the CLI-backed adapter and current live evidence in [Deployment](DEPLOYMENT.md).
4. **Historical RLP report:** the previous reconciliation directly observed that a malformed 65-character action ID returns a contract error, while the corrected 64-character ID returns state. The exact old RLP stack was not reproduced; no evidence supports attributing it to the current contract. Do not conflate that input/read decoding issue with the observed Cloudflare response or current blocked socket.

The references demonstrate a usable procedure, not a way around current process restrictions. The current release route uses the official CLI with existing named wallets for deployment and the resumable live suite, confirms chain 61999, then collects finalized receipts/readbacks and `genlayer code` parity. Do not create/import wallets, export keys to bridge tooling, bypass profile protections, or treat reference deployments as BoundaryOS evidence.
